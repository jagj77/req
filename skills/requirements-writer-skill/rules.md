# Rules R1-R41

R1 Use complete sentence Subject+Shall+Verb+Object.
R2 Use active voice.
R3 Subject must be correct entity.
R4 Use defined terms.
R5 Prefer definite article 'the'.
R6 State units.
R7 Avoid vague terms.
Forbidden examples: fast, efficient, adequate, user-friendly, flexible.
R8 Avoid escape clauses.
Forbidden: where possible, if practical, as appropriate.
R9 Avoid open-ended clauses.
Forbidden: etc, and so on, including but not limited to.
R10 Avoid 'be able to'.
R11 Separate conditions and qualifications.
R12 Use correct grammar.
R13 Use correct spelling.
R14 Use correct punctuation.
R15 Express logical conditions explicitly.
R16 Avoid negative forms when possible.
R17 Avoid slash '/'.
R18 Single sentence.
R19 Avoid combinators joining multiple requirements.
R20 Remove purpose clauses from requirement body.
R21 Avoid explanatory parentheses.
R22 Enumerate explicitly.
R23 Use diagrams for complex behavior.
R24 Avoid pronouns.
R25 Requirement shall not depend on heading context.
R26 Avoid absolutes such as always, never, 100%.
R27 State conditions explicitly.
R28 Express conditional lists explicitly.
R29 Classify requirements.
R30 Express requirement once.
R31 Prefer solution-free statements.
R32 Avoid ambiguous universals.
R33 Use ranges and tolerances when needed.
R34 Make measurable.
R35 Avoid indefinite temporal expressions.
R36 Use consistent terminology.
R37 Define acronyms.
R38 Avoid unexplained abbreviations.
R39 Apply style guide.
R40 Group related requirements.
R41 Structure requirement sets.
